# 無障礙收據補登

會員可在預約頁開啟「無障礙模式」，直接拍攝收據，不必先建立預約。模式偏好保存在裝置上；畫面使用大字、大按鈕，直接呈現目前符合資格且未被預約保留的票券，以及票券條件、有效期限。尚未領取的票券會明確標示；此畫面不自動領取或核銷。

收據流程：`pending_upload → awaiting_review → bound`。上傳完成只送交審核，會員不能自行登記完成、修改點數或服務時間。每位會員同時保留一張未綁定的待審收據；重新拍攝會在新圖片驗證成功後取代舊快照，上傳失敗會保留原快照。管理員可退回收據，讓會員重拍。

管理端「用戶預約」中的「無障礙收據・等待補登」可核對圖片並選擇：

- 新增已完成服務：填寫營業日、開始時間、實際項目、每次分鐘與次數。以目前設定的主要技師建立項目明細，沿用既有服務時間／集點結算。
- 連結已有預約：只允許同一會員已確認或已完成、且尚未綁定收據的預約。已確認預約沿用原項目結算；已完成預約只補綁收據，不再發點。

新增補登只接受已結束的服務、有效項目與有效主要技師。正常線上預約的提前天數、過期時段與休假限制仍保留。回溯日期的例外限於有已驗證會員收據的管理端補登。收據與預約的實際外鍵沿用 `booking_receipts.booking_id`，避免新增反向外鍵造成既有 Data API 關聯查詢歧義。

點數與會員服務分鐘遵守現有主要技師、服務類型及 `counts_toward_membership` 規則；固定到店項目不計入會員服務時間。未設定服務集點規則時只記錄服務時間，表單會明確提示，禁止自行假設發點比例。

API 維持 LINE 身分驗證、會員狀態／條款、維護／撤銷、管理員權限與頻率限制。收據存於私人 Storage bucket，查看使用 120 秒簽署 URL。新增 RPC 僅允許 `service_role`；補登与退回 RPC 另外驗證有效管理員。會員鎖、收據鎖、版本检查與既有唯一結算共同避免競態與重複發點，所有結算和綁定在同一交易完成。

驗證：589 項回歸測試、67 項整合測試及收據 Edge Function 型別檢查通過。正式資料庫用回復式測試確認 60 分鐘／2 點、重試只有一筆結算、延遲約束有效，測試資料全部 rollback；部署後驗證未登入请求與錯誤操作端被拒絕。LINE 內相機與實際手機畫面仍需裝置驗收，執行環境無可用視覺瀏覽器。

部署：先套用 `booking_accessible_receipt_registration` migration，再部署 `booking-receipt-api`，最後發布前端。回復時先發布前一版本前端／API；新增可空欄位可暫時保留，避免刪除已提交的收據或服務紀錄。schema migration 檔名與已套用的正式 migration 版本一致。
